How it works

Each interval's call volume and handle time become a traffic load in Erlangs. The Erlang C formula gives the smallest agent count whose modeled service level meets the target, then shrinkage (breaks, training, absence) is added on top. The scheduled line comes from the demo shift plan in data.js.

Model limitations

Erlang C assumes calls arrive randomly (Poisson), handle times vary exponentially, callers never hang up, and each interval is steady-state. Real contact centers break all of these at times. Treat the output as an illustrative planning estimate, not an operational staffing guarantee, and sanity-check it against your actual intraday reports. "Time understaffed" is how long the schedule falls short, not agent-hours missing.
